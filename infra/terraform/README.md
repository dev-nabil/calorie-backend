# Infrastructure (M0-T7, DEC-17)

Terraform for one Nouri environment per root: `envs/staging` and `envs/prod` both call `modules/nouri`.

| Layer | Resources |
|---|---|
| GCP | VPC + subnet (Cloud Run Direct VPC egress), Artifact Registry `nouri`, Cloud Run `nouri-api-<env>` (public, min 2 in prod) and `nouri-worker-<env>` (internal, always-on CPU, min 2 in prod) from one image, Memorystore Redis 7.2 (`noeviction` for BullMQ; STANDARD_HA in prod), Secret Manager (one secret per env var), service accounts per role, Workload Identity Federation for GitHub Actions, API domain mapping |
| MongoDB Atlas | Project, dedicated cluster (M30 + compute and disk auto-scaling in prod, M10 in staging), backups + point-in-time restore, VPC peering to the GCP network, IP access list = Cloud Run subnet only, one `readWrite` user per app (`nouri-api`, `nouri-worker`) |
| Cloudflare | Proxied CNAME for the API, managed WAF (Cloudflare Managed + OWASP), edge rate limits for `/v1/auth/*` and AI routes (`/v1/scans`, `/v1/meals/parse`, `/v1/conversations/*/turns`, `/v1/voice/speech`), R2 bucket for photos, thumbnails, exports and pre-rendered audio |

No job scheduler is needed: the worker runs every schedule (reminders minute job, purge, reconcile, sweeps) through BullMQ job schedulers.

## Bootstrap (per environment)

1. Create the GCP project and a GCS state bucket (versioning on); copy `backend.hcl.example` → `backend.hcl` and `terraform.tfvars.example` → `terraform.tfvars` (both gitignored).
2. Credentials in the shell only: `gcloud auth application-default login` (or a CI identity), `MONGODB_ATLAS_CLIENT_ID`/`MONGODB_ATLAS_CLIENT_SECRET`, `CLOUDFLARE_API_TOKEN` (Zone DNS/WAF/Rulesets + Account R2 edit).
3. `terraform init -backend-config=backend.hcl && terraform plan -out plan.tfplan`. Review, then apply from the reviewed plan.
4. Fill the external secrets listed in the `external_secrets_to_fill` output (never through Terraform):
   `printf '%s' "$VALUE" | gcloud secrets versions add nouri-prod-GEMINI_API_KEY --data-file=-`
   (Gemini, Resend, RevenueCat API key and webhook secret, Turnstile, Firebase and Play Integrity service accounts, the R2 access key pair from an R2 API token, Sentry DSN).
5. Set GitHub environment variables from the outputs: `GCP_PROJECT_ID`, `GCP_REGION`, `GCP_WORKLOAD_IDENTITY_PROVIDER`, `GCP_DEPLOY_SERVICE_ACCOUNT`, `API_BASE_URL`, `API_RUN_HOST`; give the `production` environment required reviewers.
6. Cloudflare: SSL/TLS mode **Full (strict)**; the CDN Worker that checks `CDN_SIGNING_KEY` signatures in front of R2 is still to be written (handoff "Not built yet").

Generated by Terraform (in Secret Manager, therefore also in state; keep the state bucket private and encrypted): JWT secrets, OTP and ledger peppers, CDN signing key, MongoDB URIs per app, Redis URL.

## Notes and choices

- **Ingress:** the API service accepts all ingress because Cloudflare reaches it over the public Cloud Run domain mapping. To lock it to Cloudflare, put a global HTTPS load balancer with a serverless NEG and a Cloud Armor allowlist of Cloudflare ranges in front (not in Phase 1).
- **Proxies:** `TRUST_PROXY=2` (Cloudflare + Google front end) so per-IP limits use the real client address.
- **Redis:** private IP, AUTH on, no TLS inside the VPC (enable `transit_encryption_mode` plus `rediss://` if required).
- **Worker scaling:** Cloud Run cannot scale on queue depth; raise `worker_min_instances` when the `scans` queue wait p95 exceeds 5 s (runbook).
- **Rate-limit rules** need a Cloudflare plan that allows 60-second periods and the chosen mitigation timeouts (Business or Enterprise); lower plans accept only 10-second periods.
